一、需求背景

生活服务分析师既承担日常取数、清洗、看板和问答，也需要独立完成商家增长、交易效率与生态健康的专题研究。用户希望AI嵌入整个过程，释放基础产能并沉淀团队方法。

本设计假设：重复加工、多工具切换、指标解释不一致及结论不可追溯，会延长从问题发现到策略执行的时间。这些是设计假设，尚未通过团队访谈与工时记录验证。

事实来源：用户需求与范围确认。暂无真实业务数据、团队基线或收益观测。公开平台文档只用于核对券、核销、门店映射和退款等对象，不代表已获取内部系统或官方指标口径。

二、需求目标

让分析师把更多时间用于判断与策略验证，以更少重复劳动产出可信、可落地、可复用的洞察。

用户结果衡量指标统计口径预期方向目标值
更快获得可信答案从提问到可复算答案的耗时已核对任务从首次提问到答案被接受的耗时中位数，按难度分层↓待基线确认
减少重复基础劳动净节省工时同类任务人工耗时减去工具使用、审核和返工耗时，以抽样工时记录计算↑待基线确认
提升结论可信度证据完整率 / 纠错率具有口径、快照、方法和复算材料的结论占比；另记录评审纠错占比完整率↑ / 纠错率↓待基线确认
让洞察进入执行建议有效采纳率有负责人和验证计划且进入执行的建议数 / 通过评审的建议数↑待基线确认
减少方法重建有效复用率被他人用于新项目且通过评审的模板次数 / 模板启动次数↑待基线确认
支持可验证增长增量核销收益与护栏优先通过实验估计，结合补贴和运营成本；无因果识别时仅报告观察变化收益↑ / 护栏不恶化待基线确认

工具使用次数和报告数量不能直接代表增长。先采集团队基线，再确定目标。

3.1 跨页规则

规则执行要求
R1 范围快照业务域、地域、行业、对象粒度、时间、对照周期、时区与口径版本随任务保存；切换全局筛选不改写已有专题。
R2 指标语义支付按支付日、核销按事件日；核销撤销与退款分别处理；商家、门店、订单、券和券核销次数不能混用。
R3 队列成熟退款和核销转化在同一支付队列及观察窗内比较。未成熟数据标注不完整，不将当期核销金额/当期支付金额称为核销转化率。
R4 质量闸门新鲜度、主键、缺失、关联覆盖和业务对账失败时，阻断新结论；历史报告保留快照，不伪装实时。
R5 证据等级区分事实、描述性贡献、相关假设、因果证据。每条发现带版本、范围、口径、方法与局限；证据不足输出缺口与补充任务。
R6 授权审计生产需角色、地域、业务域、行列权限，敏感标识脱敏；查询、导出、分享和审批留痕。原型不代表真实鉴权。
R7 评审版本生成即草稿；人工审核后才进入复用。策略或证据变更使旧评审失效；生产保留历史版本，原型要求重新生成报告。
R8 任务治理生产任务包括待确认、排队、运行、待评审、完成、失败、取消；提供阶段耗时、预算、重试和幂等。原型仅短时模拟。
R9 科学有效性时间切分防泄漏；实验随机单元一致；聚类、SRM、样本成熟、护栏、多重检验与停止规则前置校验。
R10 本地演示一个自建专题，可在设置确认重置。本地存储不跨浏览器同步；模型、调度、外部发布和策略投放未接入。

3.2 业务指标框架（建议口径）

目标指标统计要求
商家增长首单转化 / 动销留存固定入驻或动销队列，观察后续首单与留存；观察窗和有效状态待确认。
交易效率支付金额 / 核销金额分别按支付事实与核销事实汇总，保留券金额分摊与撤销冲回；与结算区别。
交易效率支付→核销转化同一成熟队列的核销有效券数 / 队列有效券数；部分核销、次卡和券类型待确认。
生态健康7日退款率支付队列7日内成功退款的去重订单数 / 队列订单数；只展示成熟队列。
生态健康投诉率 / 履约风险固定履约队列的有效投诉订单比例；投诉去重、观测窗、风险阈值待确认。
策略收益增量核销收益有效对照下估计策略效应并核算成本；不能用相关变化冒充因果收益。

六、详细方案

九个主界面及两个关键状态。表内描述为原型行为；生产要求在能力矩阵和共享规则中列明。

一级模块二级功能原型描述
工作台1. 经营概览

打开对应原型状态

【页面元素】

1、九个导航入口、搜索、动态、设置；地域/周期筛选、指标、趋势、关注项与项目。

【交互说明】

1、开始诊断进入异动；商家或退款关注项进入对应问答。

2、切换地域周期同步指标与趋势，并清除当前诊断状态；已有专题保留快照。

3、查看指标口径；搜索功能跳转；设置可确认重置。

【边界说明】

1、地域为固定比例合成切片；退款率使用更早已成熟队列，不能当作当期交易转化。

数据生产2. 资产与质量

打开对应原型状态

【页面元素】

1、四项建议资产与粒度状态、五项质量检查、新建任务。

【交互说明】

1、查看资产说明；新建任务展示加工步骤并下载配置草稿。

2、模拟数据延迟切换阻断；模拟修复并重检恢复可分析状态。

【边界说明】

1、配置下载不会创建真实调度；实验日志始终为待对接。

数据生产3. 数据延迟状态

打开对应原型状态

【页面元素】

1、延迟提示、质量失败与修复按钮。

【交互说明】

1、新诊断、问答、模型方案与报告按质量规则停止生成。

2、修复演示后回到诊断重新运行。

【边界说明】

1、已有报告只作为快照查看；演示修复不执行真实补数。

智能问答4. 业务问答

打开对应原型状态

【页面元素】

1、输入框、三个示例、上下文、资产和回答规则。

【交互说明】

1、回车或发送提交问题，Shift+Enter换行；新对话清空会话。

2、支付问题引导诊断；商家问题引导分层；退款问题解释成熟队列。

3、点击证据查看复算和未执行查询草稿。

【边界说明】

1、空输入提示；非示例主题坦诚说明无真实AI，要求明确指标和比较对象，不伪造答案。

异动诊断5. 待运行

打开对应原型状态

【页面元素】

1、问题、分析范围、运行按钮、四步进度，贡献/趋势/假设页签。

【交互说明】

1、运行时显示处理中并禁用重复点击，随后进入演示完成状态。

2、切换页签查看互斥时段贡献、趋势和候选假设。

【边界说明】

1、质量失败禁用入口并引导修复；左侧数字为演示预览。

异动诊断6. 已完成

打开对应原型状态

【页面元素】

1、四阶段完成、AI摘要、晚间72%贡献、证据版本与缺口。

【交互说明】

1、查看证据可复核差额、贡献加总和查询草稿。

2、创建专题填写问题、名称、负责人和复盘日，保存带入当前快照。

【边界说明】

1、72%为互斥时段差额贡献，不证明供给或流量原因；缺失活动、供给和曝光数据。

专题分析7. 项目闭环

打开对应原型状态

【页面元素】

1、示例与自建专题、问题、证据快照、负责人、复盘日、待办与行动。

【交互说明】

1、新建专题必填名称、问题、负责人和日期；证据待办本地保存。

2、编辑策略和行动项；生成报告草稿进入报告中心；实验入口进入实验设计。

【边界说明】

1、第二个自建专题替换前显示说明。修改策略后报告和评审失效，需重新生成。生产多项目协作暂未实现。

建模实验室8. 方法预览

打开对应原型状态

【页面元素】

1、分层、预测、归因、因果四种方法；对象、窗口、目标和用途。分层支持用户/商家对象。

【交互说明】

1、切换方法更新适用条件；预览方案显示选定对象和窗口，加入专题可创建项目。

【边界说明】

1、仅方法草稿，不训练模型，不生成准确率、预测值或因果收益。

A/B 实验9. 设计与样本估算

打开对应原型状态

【页面元素】

1、晚间供给方案、主指标、护栏、评审清单，二项转化样本估算器。

【交互说明】

1、设计实验查看并下载草稿；填写基线、绝对MDE、流量与设计效应后计算。

2、查看评审条件了解真实日志、样本和成熟窗口要求。

【功能逻辑】

1、计算为双侧95%置信、80%功效、1:1分组的两比例正态近似，按随机单元计数，向上取整并乘设计效应。

【边界说明】

1、基线加提升必须小于100%；设计效应至少1。金额实验不能使用本二项估算器；不执行投放。

报告中心10. 报告与复盘

打开对应原型状态

【页面元素】

1、专题、周报、复盘入口，报告任务列表、评审状态、下载和归档。

【交互说明】

1、有专题且质量通过后生成草稿；下载独立HTML；勾选本地证据审核后归档方法。

2、周报仅保存每周一09:00配置；保存复盘后重新生成报告以同步结果。

【边界说明】

1、无专题先创建；未审核不得归档。无真实执行不填收益；不发送消息或创建真实自动化。

生产验收重点

  • 订单多券、部分核销、退款撤销和去重处理明确；同版本同范围复算一致。
  • 异动贡献互斥且守恒，日历效应和数据缺失可识别。
  • AI不存在引用、越权和因果夸大能被离线评测发现并阻断发布。
  • 预测无未来信息；实验按随机单元估计，SRM、样本不足或未成熟不建议全量。
  • 任务取消重试、预算限制、版本失效、导出权限与审计可验证。
